# Operations journal — 2026-09

## 2026-09-06 — OpenClaw Gateway intentionally disabled

- `openclaw-openclaw-gateway-1` is intentionally stopped on `vps-hetzner-prod`.
- The decision follows repeated memory pressure and an operator decision to keep
  the Gateway offline rather than allow automatic restarts.
- `/opt/openclaw/config`, the working data, and Docker resources remain retained
  for an owner-led recovery; this repository must not restart or delete them.
- The host inventory marks the container in `disabled_containers`, so monitoring
  excludes it from expected-container alerts.
- Re-enable only after `openclaw_firststeps` approves a resource and recovery plan.

## 2026-09-08 — maxtg-bridge external watchdog registered

The `maxtg_bridge` owner deployed an external watchdog container to the Hermes
host to observe the production bridge host from outside its failure domain.
Registered here for drift control only; this repo does not deploy it.

- Inventory: `maxtg-watchdog` container and `/opt/maxtg-watchdog` on the Hermes
  host; `maxtg-watchdog-push.timer` on the production host.
- Also added the previously unlisted `deploy-bridge-1` container to the
  production host's `expected_containers` — its disappearance would not have
  been noticed before.
- Ports: `18140` private status API on the production host, `18151` restricted
  push receiver on Hermes.
- Firewall: inbound 22 from the observer and outbound 18151 to it on the
  production host; inbound 18151 from production on Hermes. The outbound rule
  was the non-obvious one — the production cloud firewall restricts egress to
  443, which silently blocked the push channel.
- Drill: stopping `deploy-bridge-1` produced a critical alert in 42 s and a
  recovery notice on restore. Total downtime 45 s.
